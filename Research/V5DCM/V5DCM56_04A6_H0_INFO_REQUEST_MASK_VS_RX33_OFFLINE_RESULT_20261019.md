These V49 W3/W4 values are *not native CM930 0708 mailbox response values*.
- V49 does **not instantiate and run the original Connect internal CM930 event app**, so no real internal 1804.bit8 request from that original software is present on this ESP. A hypothetical original DCM would have to receive the qualifying frame with a working server/event loop, maintain the logical request word, and then have its request **actually read by the controller**. The absence of controller status polls in V49 means this last service delivery step is **NOT OBSERVED**. No request can be concluded pending or zero in a physically absent/unqueried DCM just from RX33 receipt masks.
- Although source predicate suggests 04A6 may be an internal H0->H2 trigger without FC23, this **DOES NOT prove** the heat-pump controller would poll its status without an initial successful native response; the controller is the bus master, its control policy is not recovered from this Python slave handler. Lack of controller 0708 polls and native FC23 reply are possible separate service/init barriers; causality is OPEN.

## Findings: fact/conclusion/hypothesis/unknown

**PROVEN ORIGINAL FIRMWARE SOURCE/HOST (both versions):** under a correctly initialized CM930 application, first qualifying FC16 04A6 can trigger internal H2 and the version-only request path that marks native mailbox W4 1804.bit8 (verified 40/40 guard and 8/8 event chain mock tests). A successful earlier FC23 answer is not a *code-level requirement* for this H2 path. Conversely 04BA and 085F cannot initiate H2 from H0 by this method.

**PROVEN SOURCE/NAMESPACE SEPARATION:** genuine DCM mailbox W3/W4 = *requests* (1803/1804, accessed via controller 0708 six-word service), while V49 RX33 W3/W4 = *already observed pages*. **IMPORTANT CORRECTION to ambiguous previous shorthand:** V49 RX33 W4=0000 means no 0864/count4 *received*, **NOT** evidence that a genuine 0x070C request bit was zero or never set. Likewise RX33 W3=0600 means 04A6 and 04BA were received, **NOT** 1803 request bits currently active.

**PROVEN CURRENT LOCAL XTR:** qualifying 04A6/count13 was captured repeatedly by V49 before and long after the user manual OFF/ON; absence of 0708 polls, 03E8 and 0864 in observed RX-only windows. No native TX; RX clean. Thus the bus is still sending some native 0x0F traffic, but genuine data-service request publication cannot be inferred.

**STRONGLY SUPPORTED:** The missing *observable* stage is controller polling/receiving native status 0708 and later version/config group publication rather than a total absence of 0x0F traffic. **HYPOTHESIS ONLY:** A native session-service/acknowledgment barrier or master-side state prevents these polls/exports in the current V49 state. Do NOT equate missing polls to a particular FC23 failure or send a speculative response.

**OPEN/UNKNOWN:** controller electrical owner/epoch/end of frame/exclusive response slot; if a genuine initialized Connect were substituted during current 04A6 traffic, whether/when controller would poll 0708; whether the controller would accept/ACK 04A6 without prior FC23; whether firmware would reassert info requests, actual present XTR version, and exact cause of missing 03E8. Original Python software H2 alone is not Online/OPERATION/33-of-33.
