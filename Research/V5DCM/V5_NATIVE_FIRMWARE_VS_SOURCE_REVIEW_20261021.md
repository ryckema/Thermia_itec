## OBSERVED FACTS and corrective findings

**CRITICAL — DE GPIO21 evidence is not independent/valid in output-only mode.** Native YAML declares `waveshare_rs485_direction` as `switch: platform: gpio` GPIO21. ESPHome uses a GPIO output pin, and IDF states `gpio_get_level` returns **0** if input is not enabled. V5 `EspHomePhysicalIo::de_is_high()` / `rx_and_de_low()` and B11D/watchdog use `gpio_get_level` as physical pin confirmation. Thus they cannot establish DE HIGH, and a zero return does not independently prove physical DE LOW. The positive host fixture instead sets `fake_level` to the switch command. **Actual repeat:** same original S47–51 C++ host fixture PASS with original stub; replacing only GPIO input read with documented output-only always-zero model compiles but **fails at positive p.send assertion (exit 134)**. That is a HOST counterexample, not on-device electrical failure. This source flaw may affect DE-high classification, not locally proven B11D cause.

**CRITICAL — actual candidate V5 native service never transitions to a bound or armed session in supplied YAML.** It calls `reset_boot()` and `on_complete_frame()`, but contains no `bind_qualified_controller_session()`, `install_cm930_reviewed_profile()`, or `arm_scoped()` call. Its one `set_same_owner_supervisor_wiring()` passes FALSE, and frame evidence explicitly leaves controller epoch/peer/slot/source qualification FALSE. Runtime initializes `bound_=false`. Consequently all S23–S59 physical session-path host success must be described as **source candidate/mock**, not an integrated running native gateway. The S36 TX macros remain compiler denied.

**HIGH — reset return lost between layers.** S52–58 `GuardedPort::reset_rx_only()` correctly refuses to clear an owner fault if `leave_de_rx()` or observed RX/DE-LOW fails, but `ScopedTransport23::reset_for_new_session()` calls it without propagating its boolean and clears its own `fault_` / state. The lower `PhysicalOwner` still normally rejects a new grant, so this is a **state-consistency/diagnostic and recovery contract defect**, not proof that TX actually becomes allowed.

**HIGH — same composite DE predicate supplied twice.** `GuardedPort::send()` calls `confirm_de_high(...,io_.de_is_high(),io_.de_is_high())`. Distinct switch/pad evidence is not separately passed. Even a mode-correct pad read cannot be called independently measured transceiver DE/A-B state.

**HIGH — software 'source complete' flag is not firmware/application parity.** `UnifiedNative23::source_complete()` depends on a provider-source-marked bool, a 32-page table and storage size; the separate six-handler `NativeServiceGate` is not the full runtime parity check. Original firmware shows several independent handshake/parameter completeness/onboarding/runtime state axes and semantic desired/readback/retry behavior. Host FC16 ACK, FC23 response or C2 fixture success alone is insufficient for true Connect Online native app/session readiness.

**HIGH — unresolved FIFO/drain may hold DE HIGH.** S47–51 direct IDF adapter separates FIFO acceptance from `uart_wait_tx_done`, but when drain cannot be confirmed it may retain `UnresolvedInFlight` and DE HIGH; the S52 fix latches software failure rather than proving physical safe recovery. Real ESPHome blocking/eventloop order and B11D 50ms + watchdog 1s interleaving remain untested. Test fixture manually calls an owner observer inside a mocked FIFO call; that is not evidence real callback scheduling overlaps physical TX.

**FIRMWARE PROVEN:** Connect CM930 is slave `0x0F`, responding to controller-master FC16 and FC23; mailbox desired/current request bits, controller FC03 desired pull and subsequent FC16 readback underpin writes. 2.0.18 and 2.1.105 share native handshake and selector ABI, but application/service-level completeness and per-model group/payload are not proven identical on XTR. The XTR physical `0864/count4` publication must not be confused with vendor selector span `count12`; `0867` means HP CM version in firmware, not automatically display version.
