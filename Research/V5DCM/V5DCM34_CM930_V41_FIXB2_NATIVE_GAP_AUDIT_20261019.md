### Exact current callback wiring (source facts)
- `waveshare-thermia...yaml` already calls `v5dcm33b::shadow().raw_callback` and `v5_callback` on the same UART feed as `c.parser.feed()`. The single validated native callback goes into `v5dcm23::ledger().on_native_crc_validated_bytes`, V5DCM1/2 passive observations and V5DCM32 `on_crc_frame`.
- However **the B2 shadow `QualifiedReadOnly` result is consumed only by its own logs/HA status and never as the policy input to V5DCM32 or the actual V5DCM23 RX ledger**. This is *intentional safe separation*, not an observed bus protocol failure.
- `v5dcm33b_post_gap_raw_shadow.hpp` declares `kTxAllowed=false`, `kMayQualifySession=false`; `v5dcm32_rx_rejoin_bridge.hpp` has `kCanTransmit=false`; actual ledger has `kTxAllowed=false`.
- V5DCM32's live hook uses current validated events/gap/cold/FC23 and a separate user ARM. Previous user-live rejoin was **COMPLETE / NEGATIVE** because original B11D latched `RAW_INCOMPLETE_AT_IDLE` *before* a 12923ms callback gap; no blanket reset or release justified.
- The newer 204-second B2 baseline has **no native FC23 challenge and no user ARM**, hence can neither support nor refute general native approval acceptance.

## STRONG CONCLUSIONS

1. **Most narrowly actionable cold-path gap:** missing audited **response eligibility / delivery / session-state boundary** around native FC23. Existing V5 parser/CRC/FC16 and runtime HA should be reused, not reimplemented. An upstream/personal Core state update without an actual, bounded, independently authorized delivery is not controller session acceptance.
2. **Most narrowly actionable retained/post-gap gap:** missing provenance-preserving **RX cohort/current native event to session generation join**. B2's frozen shadow is *historical* receive evidence only. Linking it must **never automatically override B11D/P5 sticky faults, infer epoch/owner, authorize ACK/TX, or reset profile**; current V5DCM32 accepts only a distinct user-scoped risk policy.
3. **Distinct later app gap:** full 33-profile significant package receipt and parameter-map readiness. Native FC16 presence (1/33), old Stage-D 32/32 and real Online are not synonyms.
4. **Important source-version blocker:** user-private FIX-B2 portable Core is NOT the current firmware-repo HEAD. In private B2 the `fc16_decision` API is mutable/ticketed; firmware GitHub HEAD has a `const` classifier and a separate commit boundary. Before any new session-coordinator coding, explicitly choose and pin one implementation; perform interface/regression reconciliation rather than silently copying Core source across branches.
