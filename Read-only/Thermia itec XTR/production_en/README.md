# Thermia iTec XTR M — passive English monitoring

**XTR-PASSIVE-EN-01 | PREPARED / NOT RUN | SOURCE/OFFLINE REVIEW ONLY.** This build has **not** been ESPHome-target-compiled, flashed, or live validated on XTR. It is a *production-layout candidate*, not a certified production release.

## What changed

Starts from the exact public XTR M v31 FIX4 RX-only YAML at commit `9b9fc5a9d2812ebbba00df627713a2039817868c`. Removes research-only exposure to Home Assistant: 174 pre-existing disabled/raw/source diagnostic entities are set `internal: true`, leaving 84 plainly English HA measurements/status entities. Existing internal IDs and publish references remain so the source's RX parser is not broken. Device display name reads `Thermia iTec XTR M`; technical ESPHome device name `thermia-itec` is unchanged to preserve registration. No `number`, `select`, `button`, service write or experimental HA TX controls.

## Hardware and protocol

* Exclusively iTec XTR M / Waveshare ESP32-S3-RS485-CAN(-U), 9600 baud / 8E1.
* UART receive GPIO18. There is **no configured UART TX pin**; GPIO21 direction control is `ALWAYS_OFF` (DE LOW, receiver enabled).
* Observe natural controller/room/outdoor/native packets only. No 0x06/0x0F emulation, FC03 request, physical FC16 ACK, or calendar polling is generated by this ESP.
* The original RX assembler, valid-frame CRC/watchdog tracking, cache logic, and optional-feature invalidation policy are retained as-is.

## Limitations: be explicit in Home Assistant

* Settings that require controller-originated 0x0F configuration pages can remain `Unknown` after boot. Passive listening cannot force the controller to resend these pages. Do **not** invent zero/off or current values.
* A small set of heating settings is restored from validated saved cache across an ESP reboot by the inherited v31 logic. **Treat these as last known, not guaranteed fresh** until corroborated by a new native page. Avoid using cached configuration as a safety interlock.
* Pool, extra distribution circuits and buffer/hydraulics have inherited optional capability gating, including its provisional 6-hour age rule. They are not proven installed on every XTR M.
* No active session, OEM current-page refresh, fault-history/calendar read, write control or guaranteed full Thermia Online equivalence. The live native write/FC03 branch remains a separate private project.

## Build / activate (USER initiated only)

1. Save the existing **locally verified running YAML/firmware** as rollback. This ZIP does *not* include private native-session/W2R1 firmware.
2. Extract this ZIP and place the YAML in ESPHome. Supply `wifi_ssid`, `wifi_password`, `thermia_api_encryption_key`, `thermia_ota_password`, `thermia_fallback_password` in your local ESPHome secrets (never commit secrets). Review pinout and selected device before compiling.
3. Run `esphome config thermia_itec_xtr_m_passive_en.yaml` and `esphome compile thermia_itec_xtr_m_passive_en.yaml` **locally**. Stop if either fails; share compiler output only on failure.
4. On a **user-initiated** flash/OTA, let the heat pump and room sensor operate normally. Do not disconnect the room sensor. Check bus-health state, room/outdoor/supply/DHW/compressor data, no CRC/stream deterioration, and no actual physical DE/TX activity if verifying electrically.
5. ABORT: stop use/restore the last known-good firmware on RX/CRC regression, missing essential HA measurements or bus disturbance. Revert via normal ESPHome OTA/USB; do not restart or bypass the heat-pump controller to work around missing pages.
