## Hardware and protocol

* Exclusively iTec XTR M / Waveshare ESP32-S3-RS485-CAN(-U), 9600 baud / 8E1.
* UART receive GPIO18. There is **no configured UART TX pin**; GPIO21 direction control is `ALWAYS_OFF` (DE LOW, receiver enabled).
* Observe natural controller/room/outdoor/native packets only. No 0x06/0x0F emulation, FC03 request, physical FC16 ACK, or calendar polling is generated by this ESP.
* The original RX assembler, valid-frame CRC/watchdog tracking, cache logic, and optional-feature invalidation policy are retained as-is.

## Limitations: be explicit in Home Assistant

* Settings that require controller-originated 0x0F configuration pages can remain `Unknown` after boot. Passive listening cannot force the controller to resend these pages. Do **not** invent zero/off or current values.
* A small set of heating settings is restored from validated saved cache across an ESP reboot by the inherited v31 logic. **Treat these as last known, not guaranteed fresh** until corroborated by a new native page. Avoid using cached configuration as a safety interlock.
* Pool, extra distribution circuits and buffer/hydraulics have inherited optional capability gating, including its provisional 6-hour age rule. They are not proven installed on every XTR M.
* No active session, OEM current-page refresh, fault-history/calendar read, write control or guaranteed full Thermia Online equivalence. The live native write/FC03 branch remains a separate private project.

## Return Temperature status-publication correction (2026-10-27)

User XTR OTA log from uptime 33–128 seconds shows valid live condenser/ODU updates and return sensor repeatedly published `nan °C` every roughly 2 seconds. Existing native `0x0F:07D2` page decoder uses `valid_whole_temp` and already reports unavailable values as NaN. A one-branch SOURCE correction now emits NaN only on first invalid observation or a valid-to-invalid transition. Other readings and decoder/CRC/DE/TX/HA IDs are identical. This removes repeated invalid log churn but **does not make the return measurement available**. No source value was substituted; an actual valid 07D2 is still published normally. SOURCE/OFFLINE ONLY, new build not target-compiled/OTA/live tested. Previous OTA showed API handshake and readings, not electrical TX-free proof or longitudinal full coverage.

## Passive XTR invalid-update optimisation (2026-10-27)

Following user XTR evidence of repeated invalid Return Temperature publishes, the previous targeted 07D2 guard is retained. The same **state-transition-only invalidation** is now applied to 48 pre-existing NaN publication sites in the native XTR decoder: publish NaN only if no prior state has been reported or the last state was numeric. Valid-to-valid updates are identical. This reduces repeated log/API churn when optional/native temperatures are unavailable, but cannot manufacture missing native controller pages, signal fresh cache, or convert condenser inlet into return temperature. No IDs, ESPHome names, UART/DE/CRC/framing/TX, feature flags, threshold policies, settings cache, or other measurement semantics were changed.
