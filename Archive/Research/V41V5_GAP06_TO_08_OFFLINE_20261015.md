## GAP-06 — COMPLETE/POSITIVE scoped fixture and patched-host tests; NEGATIVE old retained write-base; INCONCLUSIVE raw replay

- **Hypothesis:** report-derived local-XTR event transitions can be represented without conflating separate ESP/controller episodes, and cached configuration pages must not retain semantic write authority across retained-session requalification.
- **Baseline:** GAP-01..05, original portable C++ `xtr_core.cpp`, earlier documented local XTR S11 transitions. **Controlled change:** offline C++ fixture harness and 12 provenance-labelled *report-derived* event points, plus separately patched **host-only** source copy. No installed source change.
- **Result:** 12/12 provenance-labelled points; 108/108 original host characterization assertions and 108/108 patched tests; baseline 69/69 semantic, 46/46 revocation, 114/114 GAP-03 regressions pass on patched copy. **Original core negative:** `begin_retained()` retained stale `Page.write_base` and synthetic requalification admitted use of an old page as an authoritative base. Candidate host fix invalidates cached write-base authority without destroying diagnostic page bytes.
- **Relevant fields:** native page ownership/freshness and lifecycle, not new register write targets; documented S11 runtime families are separate manual historical runs, not one continuous proof.
- **Positive:** candidate host invariant in tested contexts MET. **Negative:** original stale write-base retained and re-admission confirmed. **Inconclusive:** full original-XTR raw byte-by-byte replay and W0–W5 parity NOT RUN. **Abort/recovery:** any inferred universal owner, unsolicited TX or stale deployed-source modification => stop; deployed V5 RX-only unaffected.

## GAP-07 — COMPLETE/POSITIVE for scoped offline lifecycle core and regression

- **Hypothesis:** invalidate write-base authority on both `begin_retained()` and `begin_recovery()`, preserve page cache diagnostically, allow writes only after a fresh authoritative page in a qualified host state.
- **Baseline:** GAP-06 original/candidate core; GAP-03/04 and semantic/revocation regressions. **Controlled change:** two explicit cached-page `write_base=false` invalidation paths in an isolated **offline C++ copy**. No cache values, CRC, selectors, new registers, output or frame geometry changed.
- **Result:** GAP-07 57/57; GAP-06 108/108; semantic 69/69; session revocation 46/46; GAP-03 114/114; GAP-04 136/136, **530/530** compiled host assertions against the candidate core using C++17 and strict compiler warnings. Retained, recovery, successive transitions, transaction cancellation, stale readmission refusal and fresh page requalification included.
- **Positive:** scoped stale write-base revocation and no regression MET. **Negative:** no assertion failures in tested source. **Inconclusive:** full on-device/session integration not run; `set_runtime_normal(false)` / `set_mailbox(false)` do not independently revoke write-base and remain a separate policy question.
- **Abort/recovery:** unexpected write-base resurrection, altered page contents or output permissions => reject candidate; keep original installed RX-only.
