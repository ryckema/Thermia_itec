## Design contract — observable code semantics

1. One **automatic passive** callback gap witness per ESP32 boot; `WAIT_GAP` until R6-P24 gap count advances and gap length >=5000ms. No user action/restart requested. Observe **only one** gap; any second gap during qualification leads to permanent `FAULT_NO_RELEASE`.
2. `WAIT_CLEAN_ANCHOR`: entirely discard first return callback from the *new cohort*, plus all pre-anchor callback bytes. Observe the existing V5 parser; demand at least one CRC-valid completed frame **and no V5 pending bytes** after that callback. Only then freeze resync/drop/geometry/unknown and B11C independent CRC / portable mismatch counter baselines. Mark the number of old pre-anchor resynchronizations separately (`oldResync`, cap 64), but DO NOT clear or accept them as CRC-good or native protocol evidence. No physical EOF claim: this is a **software-parser clean anchor**.
3. `CLEAN_COHORT`: starting **with the next callback** after that anchor, buffer independently copied raw UART bytes (bound 4096). Original portable `known_rtu_slave/function`, `candidate_lengths` and independently calculated `valid_crc` split the new bytes; compare the exact complete frame set byte-for-byte with unchanged V5 emitted frames (bounded 128 expected). Wait >=25ms software quiet and allow <=250ms on a fresh partial; a genuine ongoing partial that does not finish fails closed.
4. Abort/record `FAULT_NO_RELEASE` on new post-anchor V5 resync/drop/geometry/unknown, new B11C CRC/portable mismatch counters, extra long gap, overflows, output/DE activity, corrupt/incomplete RAW frame, byte/count disagreement, or total window >90s. **No automatic retries or re-arms.**
5. Only after >=30 seconds **from clean anchor** and >=50 independently CRC-valid, byte-identical frames, freeze terminal historical status `RX_SHADOW_RECORDED`; no release when the observation window later expires. Always show `B11D_history` and `P5_history` separately; `TX=HARD_DENY OWNER=UNKNOWN`. This is HISTORICAL DIAGNOSTIC PROOF, **not continuously valid RX authorization**. Old FIX2 / B11D / P5 remain fully authoritative for every other purpose.

**Negative criteria:** post-anchor parser/CRC/portable/raw mismatch; no clean anchor by 90s; output observed; incomplete new frame >250ms; lost RX. **Inconclusive:** no new >=5s gap witnessed or log too short; this MUST NOT be called a live failure. **Positive on-device ONLY after user-supplied log** showing the exact status and independent count/parity. **Abort/recovery:** TX physically impossible by build flag; any unexpected DE high, UART write counter, HA failure, or unit alarm -> stop and revert to the previously verified output-disabled RX configuration via ordinary procedures. Never force physical restart simply to trigger V49; passive opportunity only.
